# 权限登录系统对接说明

> 适用对象：统一员工 Web 端、自建前端及需要接入统一身份平台的实施方。本文以当前 `open-call` 实现为准；完整接口定义见 [OpenAPI](./api/openapi.yaml)。

## 1. 接入范围与约定

- 业务 API 根地址由部署方提供，示例为 `https://cc.example.com`；本文路径均以 `/api/v1` 开头。员工 Web 端统一使用 `/`，按登录用户权限显示管理功能和坐席工作台；访客页使用 `/guest/`。浏览器只对接 `open-call`，通话接口由它代理到 `open-switch`。
- 请求和响应使用 UTF-8 JSON。请求体直接传业务字段；成功响应统一为 `{"code":"OK","message":"成功","data":...,"request_id":"..."}`。下文展示的业务结果均位于 `data` 中。
- 登录、刷新、查询登录方式以及 OIDC 流程无需 Bearer 令牌。其余用户与权限接口使用 `Authorization: Bearer <access_token>`。
- `request_id` 对应响应头 `X-Request-ID`，便于排查。含具体时刻的响应字段按 UTC `YYYY-MM-DD HH:MM:SS` 解释。
- 访客入会令牌属于另一套受限身份机制，不用于员工登录和权限管理。

## 2. 先确定登录方式

调用 `GET /api/v1/auth/options`，读取 `data`：

```json
{
  "oidc_enabled": false,
  "local_login_enabled": true,
  "local_login_emergency_only": false
}
```

`oidc_enabled=false` 时员工使用本地用户名和密码。启用 OIDC 后，员工通过统一身份平台登录；本地密码入口仅供配置的应急管理员使用。上述三个字段描述入口能力，不能代替服务端的身份校验。

## 3. 本地账号登录

### 3.1 获取令牌

```http
POST /api/v1/auth/login
Content-Type: application/json

{"login_name":"agent1","password":"<密码>"}
```

成功示例：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "access_token": "<JWT>",
    "refresh_token": "<JWT>",
    "expires_in": 3600,
    "token_type": "Bearer"
  },
  "request_id": "<请求ID>"
}
```

`expires_in` 的单位是秒，取值由部署配置决定。若 `data.must_change_password=true`，客户端应立即调用 `POST /api/v1/auth/change-password`，提交 `{"current_password":"<原密码>","new_password":"<新密码>"}`。在修改完成前，受保护接口仅允许修改密码和退出登录；修改后原会话失效，须重新登录。新密码为 12～256 字符，且包含大写字母、小写字母和数字。

### 3.2 获取当前身份和权限

```http
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

`data` 示例：

```json
{
  "user_id": "<用户ID>",
  "agent_id": "<坐席ID或空字符串>",
  "username": "坐席一",
  "login_name": "agent1",
  "employee_no": "AGENT001",
  "roles": ["agent"],
  "permissions": ["agents.read", "agents.self", "calls.operate", "calls.read", "calls.wrap_up", "guest.issue", "queues.read"]
}
```

前端按 `permissions` 控制菜单和按钮展示；每次业务请求仍由服务端检查权限及资源归属。`agent_id` 为空表示该账号没有坐席资料。用户资料中的单值 `role` 是兼容字段，运行时授权以 `roles` 所产生的有效 `permissions` 为准。

用户资料使用三个独立字段：`username` 是页面展示的用户名，`login_name` 是本地密码登录时输入的唯一登录名，`employee_no` 是唯一工号。创建用户时三个字段均必填；历史账号升级后若工号为空，可由管理员补录。用户管理接口为 `POST /api/v1/users`、`GET /api/v1/users/{userId}` 和 `PATCH /api/v1/users/{userId}`。

### 3.3 刷新与退出

```http
POST /api/v1/auth/refresh
Content-Type: application/json

{"refresh_token":"<当前refresh_token>"}
```

返回与登录相同的令牌结构。**每次刷新都要同时替换本地保存的 access token 和 refresh token**；旧 refresh token 只能使用一次。刷新失败或受保护接口返回 401 时，应清除本地令牌并重新登录。OIDC 会话刷新还会向身份平台核对授权；外部授权失效时同样需要重新登录。

```http
POST /api/v1/auth/logout
Authorization: Bearer <access_token>
Content-Type: application/json

{"refresh_token":"<当前refresh_token>"}
```

退出会撤销当前访问令牌及其登录会话；客户端在调用后清理本地令牌。也可通过 `GET /api/v1/auth/sessions` 查看本人未过期的会话，返回 `data.items` 和 `data.current_session_id`；`DELETE /api/v1/auth/sessions/{sessionId}` 撤销本人的指定会话。

## 4. 统一身份平台 OIDC 对接

部署方需要配置身份平台的 `issuer`、`client_id`、`client_secret`、回调地址、前端根地址、组声明名、应急管理员和加密密钥；这些地址可使用完整的 HTTP 或 HTTPS URL。身份平台须支持 OIDC Discovery、授权码流程、ID Token，并提供用于授权的组声明与 `employee_no` 工号属性。服务端使用 state、nonce 和 PKCE 校验登录流程。配置项见 [部署配置示例](../open-call/deploy/config.example.yml)。

1. 统一员工页跳转到 `GET /api/v1/auth/oidc/start`。服务端设置短期 HttpOnly state Cookie，并以 302 跳转身份平台。
2. 身份平台回调到部署的 `/api/v1/auth/oidc/callback`。服务端验证身份与组映射后，以 302 跳回前端根路径，URL 片段中携带 `sso_ticket`，例如 `https://cc.example.com/#sso_ticket=<票据>`。
3. 前端读取票据后立即从地址栏移除片段，再调用 `POST /api/v1/auth/oidc/exchange`，请求体为 `{"ticket":"<票据>"}`。票据有效期为 1 分钟且只能兑换一次，响应 `data` 与本地登录的令牌结构相同。
4. 后续使用本项目签发的 Bearer 令牌访问业务 API，不直接把身份平台令牌传给业务接口。

身份平台组通过项目内的“组 → 角色”映射生成权限。没有映射到任何项目角色或缺少 `employee_no` 时登录被拒绝。`preferred_username` 作为登录名，`name` 作为用户名，`employee_no` 作为工号。首次登录可自动创建项目用户；若项目内已存在相同登录名或工号，管理员须先显式绑定其外部身份，系统不会自动合并。新建的 OIDC 用户若需坐席能力，还需配置坐席资料。更改组映射会撤销既有 OIDC 会话。

## 5. RBAC 权限模型

权限链为“用户 → 一个或多个角色 → 权限码”。当前内置角色为 `admin`（管理员）、`supervisor`（班长）、`agent`（坐席）。管理员默认拥有全部已定义权限；内置角色不可修改或删除。可新增自定义角色并分配权限。完整权限目录以 `GET /api/v1/permissions` 的返回为准，例如 `users.read`、`users.update`、`roles.write`、`identity.write`、`agents.self`、`calls.operate`。

| 操作 | 接口 | 所需权限 | 主要请求字段 |
|---|---|---|---|
| 查看权限目录 | `GET /permissions` | `roles.read` | — |
| 查看角色及其权限 | `GET /roles` | `roles.read` | — |
| 创建或更新自定义角色 | `PUT /roles/{roleId}` | `roles.write` | `name`、`permissions`（权限码数组） |
| 删除自定义角色 | `DELETE /roles/{roleId}` | `roles.write` | — |
| 查看用户角色 | `GET /users/{userId}/roles` | `users.read` | — |
| 覆盖用户角色 | `PUT /users/{userId}/roles` | `users.update` | `roles`（至少一个有效角色） |
| 查看外部组映射 | `GET /identity/group-mappings` | `identity.read` | — |
| 覆盖外部组映射 | `PUT /identity/group-mappings` | `identity.write` | `group`、`roles` |
| 查看外部身份绑定 | `GET /users/{userId}/identities` | `identity.read` | — |
| 绑定外部身份 | `POST /users/{userId}/identities` | `identity.write` | `issuer`、`subject` |
| 解绑外部身份 | `DELETE /users/{userId}/identities?issuer=...&subject=...` | `identity.write` | 查询参数 |
| 管理员撤销用户全部会话 | `POST /users/{userId}/revoke-sessions` | `users.sessions` | — |

表中路径均需加 `/api/v1` 前缀。`PUT /roles/{roleId}` 可创建或更新角色；`permissions` 应使用权限目录中的 code。用户角色、角色权限或账号状态变更后，受影响的已有登录会话会失效，客户端应按 401 流程重新登录。OIDC 应急管理员不能被禁用、删除、移除 `admin` 角色或绑定外部身份。

## 6. 错误处理与联调检查

失败仍保留 HTTP 状态，并返回统一结构：

```json
{"code":"FORBIDDEN","message":"无权限","data":null,"request_id":"<请求ID>","error":"forbidden"}
```

| HTTP 状态 | 客户端处理 |
|---|---|
| 400 | 检查字段、角色 ID、权限码或身份平台工号属性 |
| 401 | 凭证错误、令牌过期或会话失效；清理令牌并重新登录 |
| 403 | 已认证但没有权限，或未满足当前登录限制 |
| 409 | 登录名、工号或外部身份绑定冲突 |
| 429 | 命中请求频率限制，稍后重试 |

联调时建议至少验证：登录并读取 `/auth/me`；无令牌访问受保护接口得到 401；低权限账号调用管理接口得到 403；刷新后旧 refresh token 不能再次使用；改角色或撤销会话后旧 access token 失效；OIDC 组未映射、缺少工号和票据重复兑换均被拒绝。排查时记录响应中的 `request_id`，不要记录密码、访问令牌或刷新令牌。

## 7. 对接边界

- 客户端不得提供服务间密钥；`open-call` 验证 Bearer 令牌及通话归属后，向 Switch 填入显式操作字段。Switch 不读取 `X-Principal`。
- 权限码只负责接口级授权。坐席本人操作、通话归属等资源范围仍由后端单独校验。
- 使用 WebSocket 的员工客户端通过 `/api/v1/ws?token=<access_token>` 建立连接；令牌更换或会话失效后应使用新令牌重连。实时事件格式见 [事件协议](./events.md)。
- 生产环境由实施方通过 HTTPS 提供 API 地址并确认 `security.allowed_origins`；示例配置中的账号、密码及密钥不可作为正式环境凭据。
