# 应用音频与业务边界

## 所有权

Switch 是呼叫及实时话务的权威：Call/Leg 状态、SIP/WebRTC、DID、队列、ACD、坐席容量、桥接、录音和技术媒体资源。call 是业务权威：用户权限、通知任务、音频内容、模型接入、提示词、对话策略及业务结果。

人工设备继续使用 WebRTC 或 SIP/RTP。机器人在 call 中维护模型会话，通过通用 PCM 接口接入已经应答的坐席腿。固定 WAV 通知在 call 中维护任务，通过通用单腿 SIP 拨号和原生播放完成业务，无需创建人工或机器人坐席腿。

未来实时合成的单向业务可添加 `application` 腿，使用同一个 PCM 会话的 `sendonly` 方向。application 腿不绑定坐席；机器人保留 agent 腿，因为其坐席容量仍由 ACD 管理。

## 共用技术能力

`open-switch/internal/layers/media/application.go` 为播放与流式音频提供输出缓存、尾帧补齐及输出结束判断。`mix_scheduler.go` 使用现有 20 ms 媒体时钟，将应用输出、普通坐席媒体交给相同的混音、编码、RTP 和录音路径。素材使用 Switch 的 WAV 解码和重采样能力，立体声下混为单声道。

既有 IVR/排队等待音由 Switch 的 IVR 引擎管理，不能由业务播放的停止操作取消。通用播放按 call、leg、playback ID 精确定位。直接桥接的播放保留原媒体转发，并使用独立提示轨或 SIP 音频输出；PCM 双向会话要求混音房间。

当前电话混音工作区仍为 8 kHz。PCM 接口接受 16/24/48 kHz 是为了适配模型格式，不表示电话链路升级为宽带。

## PCM WebSocket

内网接口：

```text
GET /switch/v1/calls/{callId}/legs/{legId}/media
    ?direction=duplex&input_rate=16000&output_rate=24000
```

须先接通通话，绑定现有 agent 或 application 腿；同一腿只能选择一个 PCM 或 WebRTC 端点。方向支持 `duplex`、`sendonly`、`recvonly`。input 是 Switch → call，output 是 call → Switch。格式固定为单声道、16 位有符号小端 PCM，采样率支持 8000/16000/24000/48000。

- Switch → call 二进制消息为原始 PCM，输入混音排除本地应用输出和业务播放，避免模型听到自己的回复。
- call → Switch 二进制消息为 8 字节大端 generation 加原始 PCM。单块不得超过 1 秒，不接受半个 PCM 样本。generation 初始为 1。
- 文本 `{"type":"output.clear","generation":2}` 清空旧输出并推进 generation；后续迟到的旧 generation 音频丢弃。新 generation 必须递增。
- 文本 `{"type":"output.finish","generation":2}` 声明该次输出结束，补齐不足一帧的尾部；缓冲播放完及尾部余量结束后发出 `output.finished`。
- 每块输出收到 `output.accepted`、`output.backpressure` 或 `output.discarded`。Switch 输出最多排队 5 秒，SDK 按反馈等待容量；单次发送等候最多 10 秒。等待容量不阻塞清空操作。
- 输入最多缓存 100 个 20 ms 帧（2 秒），应用不读取时关闭会话。单次网络写入最多 5 秒。连接关闭只释放应用媒体会话；是否挂断由 call 业务决定。

SDK 位于 `open-call/internal/integration/switchapi/application_media.go`，提供 `OpenPCM/Send/Receive/Clear/Finish/Close`。使用发送接口时必须并行读取，以接收容量反馈。模型适配器的交付队列最多 10 秒，避免等待 Switch 容量时阻塞 VAD 事件；它不执行电话编解码、重采样或媒体发送节拍。

模型 `response_id` 与 generation 共同隔离回复。说话开始事件清空服务器待播音频，被取消回复的迟到音频不再下发。移除腿、挂断和转交负责回收连接；机器人错误清理只在仍持有该通话坐席腿时请求挂断。打断能力仍需在实际模型网关上验收。

## 原生播放

```text
POST   /switch/v1/calls/{callId}/legs/{legId}/playbacks
GET    /switch/v1/calls/{callId}/legs/{legId}/playbacks/{playbackId}
DELETE /switch/v1/calls/{callId}/legs/{legId}/playbacks/{playbackId}
```

POST 提交 `asset_id`，支持 `expected_version`、`Idempotency-Key`。重复同一键返回同一 playback ID，改变素材返回冲突。只允许已接通通话及已连接的目标媒体腿。同一目标同时只运行一个业务播放；每通话最多保留 128 个播放结果。

状态为 `playing/finished/stopped/failed`。事件包括 `leg.playback_started`、`leg.playback_finished`、`leg.playback_stopped`、`leg.playback_failed`。服务器输出最后一帧后保留 200 ms 尾部余量，之后才认定结束；`completion_scope=server_output` 明确不承诺对端已经听到。网络和终端缓冲无法由服务器完整确认。

停止一条腿的播放不会停止其他腿、IVR 或排队等待音；腿离开和房间关闭会取消关联播放。

## 通知业务与持久化

call 数据表 `oc_voice_notifications` 保存发起用户、请求幂等键、号码、素材、通话腿、播放 ID、状态及错误。后台任务独立于 AI 开关启动，通过短租约处理任务。租约阻止多个 call 实例同时推进同一任务，调用失败时先清理已创建通话；不会自动重复拨打客户。

状态推进：`queued → dialing → playing → finishing → completed`；取消或错误进入 `stopping`，挂断后转为 `canceled/failed`。整体任务期限为 10 分钟。发起人用于权限和审计，不加入服务腿，不占坐席容量。Call 重启后继续核对任务，稳定的 call ID、拨号键和播放键避免重放。Switch 重启会结束既有媒体会话，任务据此失败，不自动重拨。

此版本实现单次固定素材通知，没有引入批量调度、新的消息队列或独立部署服务。模型业务和通知业务各自维护状态、取消和错误处理。

## 删除的旧路径与升级

已删除 Switch `POST /calls/voice-notifications`、`prompt_outbound` 模式、`prompt_asset_id/outbound_mode` 技术视图字段及其专用呼叫控制逻辑。call 中删除机器人 Pion/WebRTC、PCMU 编码、WAV 播放、重采样和本地 pacer，依赖随之清理。call 的业务通知入口保留，但返回持久化任务。

1. 停止新任务并排空现有通话及旧通知；备份数据库和配置。
2. 协同升级 Switch、call、前端。不要让新 call 连接旧 Switch。
3. call 启动时执行新增迁移 `000004_voice_notifications.sql`，创建业务任务表；既有历史话单不变。
4. 删除 `aibot.username/password/wideband_webrtc`；保留机器人 agent ID、队列及模型业务配置。通知无需 AI 账号或 AI 开关。
5. 使用人工 WebRTC、人工 SIP、机器人双工和通知单向四条实际媒体路径验收，检查拒接、断线、尾音、取消、打断、转交、录音和容量隔离。

本地自动化覆盖输出上限、迟到音频隔离、PCM/RTP 格式、播放范围、幂等拨号与播放、任务完成和取消。真实中继、终端及模型网关的音频效果须在联调环境确认；单元测试不能替代实际通话验收。
